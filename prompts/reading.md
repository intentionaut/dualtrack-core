
## Reading: only what the step needs

Every read costs the run's budget and crowds out what matters. Read narrowly, then act.

- Start from the files and paths the run names. Do not Glob or Grep the whole repo to orient yourself.
- Search before you open: Grep for the name, heading or date you need, then Read only around the hits with `offset` and `limit`.
- Read a whole file only if it is short (under about 200 lines) or you are about to change most of it.
- Records grow every day: in `decisions.md`, `bets.md` and `team-log.md`, read the lines since the last memo or run (Grep the date), not the whole history.
- Never read the same file twice in one step. Never print a file through Bash when Read or Grep will do.
- Stop reading once you can answer. If your answer has a Read line, name there anything you chose not to read, so a reader knows what the answer rests on.
